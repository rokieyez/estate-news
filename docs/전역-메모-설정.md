# 모든 프로젝트에서 기억하게 만들기

저장소 안의 `CLAUDE.md` 는 **이 저장소에서만** 읽힙니다.
새 프로젝트를 열어도 같은 내용을 읽게 하려면 아래처럼 설정하세요. **한 번만 하면 됩니다.**

---

## 왜 따로 설정해야 하나

Claude 는 시작할 때 정해진 위치의 메모 파일을 읽습니다.

| 위치 | 적용 범위 |
| --- | --- |
| `저장소/CLAUDE.md` | 그 저장소에서만 (지금 이 저장소가 이 방식) |
| `~/.claude/CLAUDE.md` | **내 모든 프로젝트** ← 우리가 원하는 것 |

문제는 **클라우드(claude.ai/code)에서 쓸 때**입니다.
클라우드는 일이 끝나면 작업용 컴퓨터를 통째로 반납해서, 그 안에 만든 파일이 사라집니다.
그래서 세션이 시작될 때마다 **자동으로 다시 만들어지도록** 해야 합니다.
그 역할을 하는 것이 **설정 스크립트(Setup script)** 입니다.

> 설정 스크립트가 만든 파일은 저장돼서 다음 세션에도 그대로 남습니다.
> 스크립트를 고치거나 약 7일이 지나면 다시 실행됩니다.

---

## 하는 법

1. [claude.ai/code](https://claude.ai/code) 로 갑니다
2. **환경(Environment) 설정** 을 엽니다
3. **Setup script** 칸에 아래 내용을 통째로 붙여넣습니다
4. 저장합니다

이제 어떤 프로젝트를 열든, 새 창을 열든 Claude 가 이 내용을 먼저 읽습니다.

---

## 붙여넣을 내용

```bash
#!/bin/bash
mkdir -p ~/.claude
cat > ~/.claude/CLAUDE.md <<'CLAUDE_MD_END'
# 사용자 정보 (모든 프로젝트 공통)

- 유튜브 콘텐츠 제작자이자, 영상 제작을 의뢰받아 납품하는 프리랜서입니다.
- 개발자가 아닙니다. 코드와 터미널에 익숙하지 않습니다.
- 한국어로 소통합니다.

## 저에게 설명할 때
- 전문 용어를 쓰지 마세요. 꼭 써야 하면 그 자리에서 한 번 풀어 주세요.
- "Settings → Pages → Enforce HTTPS" 처럼 클릭 경로를 짚어 주세요.
- 터미널 작업을 전제하지 말고, 브라우저에서 끝나는 방법을 먼저 알려 주세요.
- 자동으로 안 되는 일이 있으면 돌려 말하지 말고 이유와 함께 알려 주세요.
- 무엇을 확인했고 무엇을 확인하지 못했는지 구분해서 말해 주세요.

- 깃허브 계정: rokieyez
- 도메인: rokiz.net 은 제가 직접 구매한 개인 도메인입니다.
  GitHub Pages 커스텀 도메인으로 연결해 두었습니다. 설정 오류가 아닙니다.
- 블로그: 네이버 블로그를 씁니다.

## 작업 성향
- 결과물을 눈으로 확인할 수 있게 해 주세요 (링크, 화면, 예시 파일).
- 비용이 드는 작업은 먼저 얼마나 드는지 알려 주세요.

```

## 나중에 내용을 바꾸려면

같은 **Setup script** 칸에서 글자만 고치고 저장하면 됩니다.
다음 세션부터 바뀐 내용이 적용됩니다.

새로 알려주고 싶은 게 생기면 `## 제 계정과 자산` 같은 항목 아래에 한 줄씩 추가하세요.
너무 길면 오히려 잘 안 지켜지니 **200줄 안쪽**으로 유지하는 게 좋습니다.

## 내 컴퓨터에 지식 저장고 폴더를 두는 경우

바탕화면에 이런 구조를 쓰고 계시다면:

```
바탕화면/
└─ project/
   ├─ CLAUDE.md        ← 그동안 쌓아온 지식 저장고
   ├─ active/          ← 진행 중인 프로젝트
   │  └─ estate-news/
   │     └─ CLAUDE.md  ← 이 프로젝트 전용 메모
   └─ inactive/        ← 끝난 프로젝트
```

**따로 설정할 게 없습니다.** Claude 는 작업을 시작한 폴더와 **그 위의 모든 상위 폴더**에서
`CLAUDE.md` 를 찾아 전부 읽습니다.

`active/estate-news/` 에서 시작하면 이 순서로 읽힙니다.

| 순서 | 읽는 파일 | 내용 |
| --- | --- | --- |
| 1 | `~/.claude/CLAUDE.md` | 내가 누구인지 (모든 프로젝트 공통) |
| 2 | `project/CLAUDE.md` | **지식 저장고** |
| 3 | `project/active/CLAUDE.md` | (있다면) 진행 중 프로젝트 공통 규칙 |
| 4 | `project/active/estate-news/CLAUDE.md` | 이 프로젝트 전용 |

**나중에 읽은 것이 우선**입니다. 저장고에 "A로 해라"라고 써 두고
프로젝트 메모에 "여기서는 B로 해라"라고 쓰면 B가 이깁니다. 원하는 대로 동작합니다.

`inactive/` 로 옮긴 프로젝트는 그 폴더에서 작업하지 않는 한 읽히지 않습니다.
저장고는 그대로 남으니, 끝난 프로젝트에서 배운 것 중 계속 쓸 만한 내용은
저장고로 옮겨 적어 두세요.

### 주의 1 — 클라우드에서는 안 읽힙니다

claude.ai/code(웹)로 작업하면 **깃허브 저장소만** 복제됩니다.
바탕화면의 `project/CLAUDE.md` 는 그 컴퓨터에 존재하지 않으므로 읽히지 않습니다.

| 작업 방식 | `project/CLAUDE.md` 읽히나 |
| --- | --- |
| 데스크톱 앱 · 터미널 (내 컴퓨터) | ✅ 읽힘 |
| claude.ai/code (웹) | ❌ 안 읽힘 |

웹에서도 쓰시려면 둘 중 하나를 하세요.

**방법 A. 위의 Setup script 에 핵심만 옮겨 적기**
간단합니다. 대신 저장고를 고칠 때 스크립트도 같이 고쳐야 합니다.

**방법 B. 저장고를 깃허브 비공개 저장소로 만들기 (권장)**
저장고 폴더를 깃허브에 올려 두면, Setup script 가 세션마다 내려받아
`~/.claude/CLAUDE.md` 로 설치할 수 있습니다. 한 곳만 고치면 양쪽에 반영되고,
컴퓨터가 고장 나도 내용이 남습니다.

### 주의 2 — 저장고가 길어지면 오히려 안 지켜집니다

`CLAUDE.md` 는 대화를 시작할 때마다 통째로 읽힙니다.
길수록 기억 용량을 많이 먹고, 지시가 묻혀서 **덜 지켜집니다.**

**200줄 안쪽**을 권합니다. "모든 지식"을 다 넣기보다는 이렇게 나누세요.

| 넣을 것 | 넣지 말 것 |
| --- | --- |
| 두 번 이상 설명하게 된 것 | 코드를 보면 알 수 있는 것 |
| 내가 자주 고쳐주는 습관 | 한 번 쓰고 말 임시 메모 |
| 결정한 것과 그 이유 | 긴 절차·매뉴얼 (→ 스킬로) |
| 도구·계정·주소 | 이미 다른 메모에 있는 내용 |

길어지면 주제별로 파일을 나누고 저장고에서 이렇게 불러올 수 있습니다.

```text
자세한 내용은 @knowledge/영상제작.md 와 @knowledge/네이버블로그.md 를 참고.
```

다만 불러온 파일도 함께 읽히므로 **총량은 줄지 않습니다.** 정리는 결국 덜어내는 쪽입니다.

## 프로젝트별 메모는 따로

이 저장소의 `CLAUDE.md` 처럼, 프로젝트마다 다른 내용은 그 저장소 안에 두세요.
둘 다 있으면 Claude 는 **전역 메모를 먼저, 프로젝트 메모를 나중에** 읽습니다.
겹치는 내용이 있으면 프로젝트 쪽이 우선합니다.

| 넣을 곳 | 어떤 내용 |
| --- | --- |
| Setup script (전역) | 나는 누구인지, 어떻게 설명해 달라는지, 내 도메인·계정 |
| 저장소의 `CLAUDE.md` | 이 프로젝트의 구조, 결정 사항, 함정 |
