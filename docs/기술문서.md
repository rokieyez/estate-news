## 무엇이 나오나

하루치 결과는 `output/2026-09-06/` 처럼 날짜 폴더에 쌓입니다.

| 파일 | 용도 |
| --- | --- |
| **`blog-naver.html`** | **네이버 블로그 붙여넣기용.** 브라우저로 열고 버튼만 누르면 됩니다 |
| `blog.md` | 같은 글의 마크다운 판. 보관·검색용 |
| `brief.md` | 오늘의 사실 정리. 이슈별 무슨 일 / 숫자 표 / 왜 중요한지 / **확인 필요 지점** |
| `script-shorts.md` | 60초 쇼츠 대본. 자막 단위로 끊고 컷마다 **화면 지시**가 붙습니다 |
| `script-shorts.srt` | 위 대본의 자막 파일. 프리미어·파이널컷·캡컷에 그대로 임포트 |
| `script-longform.md` | 8분 롱폼 대본. 챕터·타임코드·B-roll·그래픽 지시 포함 |
| `production-notes.md` | 제목/썸네일 문구 후보, 설명란·태그·고정 댓글 복사용, 촬영 체크리스트 |
| `data.json` | 기사에서 뽑은 수치만 모은 것. 차트 만들 때 쓰세요 |
| `img-*.png` | **수치로 자동 생성한 인포그래픽.** 블로그 이미지 자리에 넣으세요 |
| `img-*.svg` | 위 그림의 벡터 원본. 색·문구를 고치려면 이걸 편집 |
| `thumb-longform.png`, `-2.png` / `thumb-shorts.png`, `-2.png` | 롱폼(1280×720)·쇼츠(1080×1920) 표지 1안·2안. 문구 후보 1·2번 |
| `checklist.md` / `.json` | 발행 전 점검표. 사이트 첫 화면 카드의 출처 |
| `sources.md` | 근거 기사 원문 링크 전체 |
| `raw/articles.json` | 수집 원본(기사 본문 포함). 같은 컴퓨터에서 `render` 로 재생성할 때 씁니다. **커밋되지 않습니다** |
| `collect.json` | 수집 건수·피드 상태만 담은 요약. 대시보드가 읽습니다 |

주간 결산은 `output/weekly/2026-W36/` 처럼 주차 폴더에 따로 쌓입니다 (`weekly.md`,
`weekly-naver.html`, `data.json`). 매주 일요일 아침 자동으로 만들어지고, `python -m rebrief weekly`
로 언제든 손으로도 만들 수 있습니다.

### 인포그래픽은 어떻게 골라지나

`data.json` 의 수치를 훑어 **생김새에 맞는 그림 형태**를 고릅니다. 주제가 매일
바뀌므로 특정 주제에 고정돼 있지 않고, 맞는 게 없으면 만들지 않습니다.

| 형태 | 언제 나오나 |
| --- | --- |
| 서울 자치구 도식 | 수치가 '자치구 N개' 이고 설명에 '가·나·다 제외' 가 있을 때 |
| 지수 비교 막대 | 증감률(%)일 때. 구간별 실제 값이 없으므로 100 기준 지수로만 그립니다 |
| 수치 카드 | 그 외 모든 수치의 기본형 |

정보량이 많은 형태를 먼저 채우고 남는 자리를 카드로 메웁니다. 장수는
`settings.yaml` 의 `images.max` (기본 3장) 를 따릅니다.

**없는 숫자는 그리지 않습니다.** 자치구 도식은 25칸에서 제외분을 뺀 수가 보도된
값과 다르면 아예 그리지 않고, 지수 막대는 각주에 '구간별 실제 수치는 보도에
제시되지 않았다' 고 밝힙니다.

PNG 변환은 크롬(또는 크로미엄)이 설치돼 있을 때만 덤으로 합니다. 없으면 SVG 만
남고 실행은 그대로 성공합니다. 네이버 블로그에는 SVG 를 올릴 수 없으니 PNG 를
쓰세요.

### 그림이 본문 자리에 어떻게 들어가나

블로그 글을 만들 때 모델이 `[이미지: …]` 자리마다 "이 자리는 어떤 수치의 그림인지"
(`image_slots[].datapoint_label`)를 함께 적어 줍니다. 프로그램은 그 라벨로 수치를 찾아
그림을 만들고, 파일명에 자리 번호를 붙입니다 (`img-1-district-map.png` = 1번 자리).

- `blog.md` 에는 실제 이미지 문법(`![…](img-1-….png)`)으로 들어갑니다.
- `blog-naver.html` 에는 그 자리가 **초록 상자**로 바뀌고 파일명이 적히며, 아래에 미리보기가
  붙습니다. 미리보기는 복사에 포함되지 않습니다 — 붙여넣기에 상대 경로 `<img>` 가 섞이면
  네이버 에디터에 깨진 그림이 생기기 때문입니다.
- 라벨이 비었거나(사진 자리) 맞는 수치가 없으면 점선 상자 그대로 둡니다.

### 추이 그래프는 언제 나오나

매일 뽑힌 수치를 `state/datapoints.json` 에 쌓습니다. 같은 지표(단위가 같고 라벨이
0.6 이상 비슷한 것)가 **사흘 이상** 쌓이면 꺾은선 추이가 다른 형태보다 먼저 선택됩니다.
첫날부터 며칠은 아무것도 안 나오는 게 정상입니다.

### 시계열·비용·링크 장부

| 파일 | 내용 |
| --- | --- |
| `state/datapoints.json` | 날짜별 수치 이력. 추이 그래프의 재료 |
| `state/costs.json` | 실행마다 쓴 토큰과 비용. `output/INDEX.md` 아래 **비용 (실측)** 절로 요약됨 |
| `sources.md` 상단 | 선정된 이슈의 기사 링크를 HEAD 요청으로 점검한 결과. 죽은 링크는 ⚠️ |

### 발행 전 점검표 (`checklist.py`)

실행 끝에 `checklist.md` / `checklist.json` 을 만듭니다. 항목: 숫자 검산 미확인, 죽은 링크,
**금지 표현 실제 검사**(블로그·쇼츠·롱폼 텍스트에서 `video.banned_phrases` 를 찾음), 블로그
분량(설정의 ±20%), 태그 수, 빈 사진 자리, 쇼츠·롱폼 발화량(cpm 기준), 실행 경고. 사이트 첫
화면의 카드는 `checklist.json` 을 읽습니다. LLM 을 못 쓴 날은 ❌ 한 줄만 남습니다.

### 금지 표현 자동 수정 (`checklist.autofix_model`)

점검표가 ❌ 금지 표현을 찾으면 그 **문장만** 잘라 저렴한 모델(`claude-haiku-4-5`)에 "같은 뜻으로,
표현 빼고" 다시 쓰게 하고 해당 산출물(블로그·쇼츠·롱폼)을 다시 씁니다. 고친 뒤에도 표현이
남으면 바꾸지 않고 ❌ 로 둡니다. 전후 문장은 `checklist.md` 맨 위 항목에 남습니다. 비용은 그날
장부에 합산됩니다. 모델을 비우면 끕니다.

### 연속 실패

`store.failure_streak()` 이 오늘부터 거꾸로 `data.json` 없는 날을 셉니다. 2일 이상이면 실패
알림 문구가 "원인 점검"으로 바뀌고 `dashboard.html` 맨 위에 빨간 띠가 뜹니다.

### 주간 결산의 추이 그림

`state/datapoints.json` 에서 그 주 안에 사흘 이상 나온 지표를 골라 최대 2장(`img-time-series-N.png`).
사이트의 주간 폴더에 같이 복사됩니다.

### PWA

`site/manifest.webmanifest` + `icon.svg`(크롬이 있으면 `icon-512.png` 도). 서비스워커는 일부러
두지 않았습니다 — 매일 바뀌는 페이지에 캐시가 남으면 어제 글을 보게 됩니다.

### 안전망 실행 · 월 예산

- 데일리 워크플로에 07:25 KST 크론이 하나 더 있습니다. 첫 단계에서 `output/<오늘>/data.json`
  이 이미 있으면 나머지 단계를 전부 건너뜁니다 (`steps.guard.outputs.skip`). 수동 실행은 항상 돕니다.
- `llm.monthly_budget_usd` > 0 이면 `state/costs.json` 의 이번 달 합계로 판단합니다.
  `budget_soft_ratio`(기본 0.8) 이상이면 `fallback_model` 로, 예산 이상이면 요약을 건너뜁니다.

### 어제와 달라진 점

브리핑 상단에 직전 날짜 `data.json` 과 이슈 제목을 유사도 0.35 로 견줘 🆕 새 이슈 / ↪️ 이어지는
이슈 / ⏹ 빠진 이슈를 적습니다. LLM 호출 없음.

### 이슈 선정 근거 (`render.explain_issues`)

이슈마다 '오늘 2위 · 매체 5곳 · 기사 7건 · 최신 09-06 22:05' 한 줄이 `brief.md` 에 붙습니다.
모델을 부르지 않고 수집 결과만 셉니다. 이슈와 묶음은 **근거 기사 주소가 겹치는 것**으로 맞춥니다 —
모델이 순서를 바꾸거나 제목을 달리 붙여도 주소는 그대로이기 때문입니다.

### 같은 주제 반복 (`pipeline._repeat_topics`)

최근 `run.repeat_lookback_days` 일치 `data.json` 의 이슈 제목과 오늘 제목을 Dice 0.5 로 견줍니다.
겹치면 점검표에 ⚠️ 로 올리고 그때 제목을 같이 보여 줍니다. 기사 단위 재탕 방지(`skip_recent_days`)와
달리 **주제 단위**로 봅니다.

### 자막 줄바꿈과 컷 리스트

`render.wrap_caption` 이 자막 한 컷을 `video.caption_max_chars`(16자)·`caption_max_lines`(2줄)로 끊습니다.
그 폭으로 안 담기면 담길 때까지 폭을 한 글자씩 넓힙니다 — 글자를 버리지 않으면서 줄 길이를 고르게 하려는 것.
두 줄로도 넘치는 컷은 점검표에 올립니다. `shorts-cuts.csv`·`longform-chapters.csv` 는 타임코드를
`HH:MM:SS:FF`(`video.cut_list_fps`)로 적고, 엑셀 한글이 깨지지 않게 BOM 을 붙입니다.

### 이번 주 볼 것 (`site/upcoming.html`)

최근 7일 `data.json` 의 `tomorrow_watch` 를 모아 Dice 0.7 이상이면 같은 말로 보고 한 번만 싣습니다.

### 발행 기록 (`state/published.json`)

`publish` 명령이나 **발행 기록** 워크플로로 날짜·주소·조회수를 적으면 사이트 첫 화면에 표시됩니다.

### 지난 글 검색 (`site/search.html`)

빌드 때 모든 날의 `data.json` 을 `search-index.json` 하나로 모으고, 페이지 안 자바스크립트가
제목·한 줄 요약·수치 이름에서 부분 일치로 찾습니다. 서버가 없으므로 GitHub Pages 에서 그대로 됩니다.

### 숫자 검산 (`verify.py`)

브리핑의 각 수치 값을 정규화(콤마·공백 제거, 부호·범위 표기 허용)해서 그 이슈의
근거 기사 제목+본문에 글자 그대로 있는지 봅니다. 상태는 **확인 / 미확인 / 대조 불가**
(본문을 수집하지 못한 기사). LLM 호출은 없습니다. 미확인이 있으면 실행 경고에도 올라갑니다.

### 모델 강등 (`llm.fallback_model`)

한도(429)·과부하(529)·5xx·연결 오류면 대체 모델로 한 번 더 시도합니다. 인증 오류나
요청 거부(4xx)는 강등하지 않습니다. 강등된 호출은 결과 경고에 적히고, 비용은 호출마다
실제 쓴 모델 단가로 계산됩니다 (`Usage.models_used`).

### 제목 기록장 (`state/titles.json`)

실행마다 블로그·롱폼·쇼츠 제목 후보가 저장됩니다. `python -m rebrief titles log` 또는
**제목 기록** 워크플로로 고른 번호와 조회수를 적으면 INDEX 와 대시보드에 유형별 평균이 나옵니다.

### 주간 결산의 반복 이슈

7일치 이슈 제목을 유사도 0.35 로 묶어 이틀 이상 나온 이슈에 `days_seen` 을 달고,
프롬프트에 "여러 날 반복된 이슈" 목록을 넘깁니다. 같은 사건을 세 번 세지 않게 하기 위해서입니다.

### 운영 현황 (`site/dashboard.html`)

최근 30일의 기사 수·피드 성공률·요약 성공/실패·그림 장수·비용을 한 장에 모읍니다.
사이트 첫 화면 아래 링크.

### 알림

`TELEGRAM_BOT_TOKEN` 과 `TELEGRAM_CHAT_ID` 가 있으면(`.env` 또는 깃허브 Secrets) 실행이
끝날 때 헤드라인·이슈 수·그림 장수·사이트 링크를 한 번에 보냅니다. Actions 가 실패하면
실패 알림이 따로 갑니다. 없으면 아무 일도 하지 않습니다.

`python -m rebrief site` 를 돌리면 위 결과가 `site/` 아래 휴대폰용 HTML 로 변환됩니다.
`site/latest/` 는 항상 최신 날짜의 사본이라 즐겨찾기 주소가 바뀌지 않습니다.
GitHub Pages 배포는 `.github/workflows/pages.yml` 이 자동으로 합니다.

이 저장소에는 개인 도메인 `www.rokiz.net` 이 Pages 커스텀 도메인으로 연결돼
있어 산출물은 `https://www.rokiz.net/estate-news/` 로 서비스됩니다.
(`https://rokieyez.github.io/estate-news/` 도 동일하게 열립니다.)
커스텀 도메인은 저장소 Settings → Pages 에 저장돼 있고 리포지터리에 CNAME
파일은 두지 않습니다 — `build_site()` 가 `site/` 를 매번 지우고 다시 만들기
때문에 CNAME 파일을 두면 배포 때마다 사라집니다.

대본 분량은 목표 길이에 맞춰 글자 수로 계산합니다. 기본값은 분당 330자(한국어 낭독 속도)이고,
말이 빠르거나 느리면 `config/settings.yaml` 의 `speaking_rate_cpm` 을 조절하세요.

## 시작하기 — 두 가지 방법

### 방법 A. 설치 없이 쓰기 (권장)

**내 PC에 아무것도 안 깔아도 됩니다.** GitHub이 매일 알아서 돌리고 결과를 저장소에 올려 줍니다.
단계별 안내는 [README](../README.md#처음-한-번만-하는-설정) 에 있습니다.

1. 저장소 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**
   - Name: `ANTHROPIC_API_KEY`
   - Secret: [console.anthropic.com](https://console.anthropic.com) 에서 발급받은 키
2. **Settings** → **Actions** → **General** → 맨 아래 Workflow permissions →
   **Read and write permissions** 선택 후 저장
3. **Actions** 탭 → **피드 점검** → **Run workflow** → 뉴스 피드가 살아있는지 확인
4. **Actions** 탭 → **부동산 데일리 브리핑** → **Run workflow** → 첫 실행

이후로는 **매일 06:45(KST)** 자동으로 돌아 7시 전에 준비되고, 결과가 `output/` 폴더에 커밋됩니다.
실행 결과는 Actions 실행 화면에서 바로 읽을 수 있습니다(브리핑 전문이 요약란에 나옵니다).

시간을 바꾸려면 `.github/workflows/daily-brief.yml` 의 cron 을 고칩니다.
UTC 기준이라 **한국 시간에서 9시간을 뺀 값**을 씁니다.

```yaml
- cron: "45 21 * * *"   # 21:45 UTC = 06:45 KST (정각은 깃허브가 밀리거나 빠뜨릴 수 있어 피함)
- cron: "0 20 * * *"   # 20:00 UTC = 오전 5시 KST
```

## 네이버 블로그에 올리기

네이버 스마트에디터는 마크다운을 못 읽습니다. `##` 같은 기호가 본문에 그대로 보이죠.
그래서 **서식이 살아있는 HTML** 을 따로 만들어 둡니다.

1. `output/<날짜>/blog-naver.html` 을 **브라우저로 엽니다** (더블클릭)
2. 위쪽 초록 바에서 **제목 복사** → 네이버 글쓰기 제목 칸에 붙여넣기
3. **본문 복사** → 본문 칸에 붙여넣기 — 소제목·표·굵게·목록이 그대로 살아납니다.
   `keynumbers.pick` 이 고른 핵심 수치(`blog.key_numbers`)는 맨 위 '오늘의 숫자' 표 + 본문 첫 등장 굵은 형광펜,
   `blog.highlight_repeats` 회 이상 되풀이된 수치는 첫 등장 형광펜·이후 `<u>` 입니다(모두 인라인 style).
   같은 핵심 수치가 썸네일 배지(`images.thumbnail(badge=)`)에도 들어갑니다.
4. 점선 상자(📷 이미지) 자리에 사진을 넣고 상자는 지웁니다
5. 맨 아래 해시태그는 그대로 둡니다 — **네이버가 본문 해시태그를 태그로 자동 등록합니다**

안내문과 상단 바는 복사 범위에 들어가지 않으니 그대로 두셔도 됩니다.

글의 문체도 네이버에 맞춰 씁니다.

- 검색으로 들어온 사람은 스크롤을 안 하므로 **첫 3줄에 결론**
- 휴대폰으로 보므로 **한 문단 2~3문장, 120자 이내**
- 제목 앞쪽에 핵심 키워드 배치
- 소제목 4~6개, 이미지 자리 3곳
- 태그 20개 (넓은 키워드 + 좁은 키워드 섞어서)

이 규칙은 `config/settings.yaml` 의 `blog.naver` 에서 조절합니다.

```yaml
blog:
  platform: naver          # markdown 으로 바꾸면 티스토리·워드프레스용
  naver:
    tag_count: 20          # 네이버 태그 상한은 30개
    image_slots: 3
    paragraph_max_chars: 120
```

## 내 채널에 맞게 고치기

품질을 좌우하는 건 `config/settings.yaml` 의 `video` 섹션입니다. 여기부터 손보세요.

```yaml
video:
  channel_name: "부동산 브리핑"
  audience: "내 집 마련을 준비 중이거나 보유 부동산의 가치 변화를 챙기는 30~50대"
  tone: "차분하고 단정한 정보 전달. 과장·단정·투자 권유 금지."
  persona: "부동산 뉴스를 해설하는 진행자. 어려운 용어는 반드시 한 번 풀어서 설명한다."
  shorts_seconds: 60         # 쇼츠 목표 길이
  longform_minutes: 8        # 롱폼 목표 길이
  speaking_rate_cpm: 330     # 본인 낭독 속도(분당 글자 수)
  banned_phrases:            # 대본에 절대 안 쓸 표현
    - "무조건 오른다"
    - "지금 안 사면 늦는다"
  cta: "도움이 되셨다면 구독과 알림 설정 부탁드립니다."
```

`audience` 와 `tone` 은 대본 문체에 그대로 반영됩니다. 구체적으로 쓸수록 결과가 좋아집니다.

다루는 주제를 바꾸려면 `config/sources.yaml` 의 `keywords` 를 조절합니다.
`weight` 가 높은 카테고리가 이슈 선정에서 우선합니다. 예를 들어 재건축 채널이라면
`공급·정비사업` 의 weight 를 3.5 정도로 올리세요.

## 뉴스 소스 관리

기본 소스는 **구글뉴스 키워드 피드 7개**(안정적)와 **언론사 부동산 섹션 피드 6개**입니다.
언론사 RSS 주소는 개편 때 자주 바뀌므로 가끔 점검해 주세요.

- 설치 없이: **Actions** 탭 → **피드 점검** → **Run workflow**
- 내 PC에서: `python -m rebrief doctor`

워크플로는 4개입니다.

| 워크플로 | 언제 도는가 |
| --- | --- |
| 부동산 데일리 브리핑 | 매일 21:45 UTC(= 06:45 KST) + 07:25 안전망 + 수동 |
| 사이트 배포 | `output/` 이 바뀌면 자동 + 수동 |
| 피드 점검 | 수동 |
| 테스트 | 푸시할 때마다 |

```
  ✅  gnews_realestate      42건   구글뉴스·부동산
  ❌  mk_realestate         HTTP 404   ...

계속 실패하는 피드는 config/sources.yaml 에서 다음처럼 꺼두세요:
  - id: mk_realestate  →  enabled: false
```

언론사 직접 피드는 **본문까지 긁어오기 때문에** 요약 품질이 더 좋습니다.
구글뉴스 링크는 리다이렉트 페이지라 본문 수집을 건너뜁니다(제목·요약만 사용).
가능하면 언론사 피드를 살려 두세요.

## 비용

하루 한 번 실행 기준, Claude 호출은 3번입니다(사실 정리 → 블로그 → 대본).
2번째 호출은 첫 호출의 입력을 캐시로 재사용합니다.

**영상 대본은 `llm.script_model` 로 따로 지정합니다.** 출력 토큰이 가장 많은 호출이라
값싼 모델로 돌리면 하루 비용이 눈에 띄게 줄고, 브리핑·블로그 품질은 그대로입니다.
캐시는 모델마다 따로 잡히므로 대본 모델이 다르면 그 호출에는 캐시를 쓰지 않습니다.
호출별 비용은 실행 결과와 `state/costs.json` 의 `by_call` 에 남습니다.

| 모델 | 하루 | 한 달(30일) |
| --- | --- | --- |
| `claude-opus-5` (기본) | 약 $0.4 | 약 $12 |
| `claude-sonnet-5` | 약 $0.17 | 약 $5 |

실행할 때마다 실제 사용량과 추정 비용이 출력됩니다.

```
💰 claude-opus-5 · 3회 호출 · 입력 40,000 (캐시읽기 20,000) / 출력 9,000 토큰 · 약 $0.435
```

더 저렴하게 쓰려면 `config/settings.yaml` 에서 바꿉니다.

```yaml
llm:
  model: claude-sonnet-5
  effort: medium      # low | medium | high | xhigh | max
```

## 명령어

| 명령 | 설명 |
| --- | --- |
| `python -m rebrief run` | 전체 실행 (수집 → 요약 → 대본) |
| `python -m rebrief run --no-llm` | 수집·정리까지만. API 호출 없음 |
| `python -m rebrief run --limit 20` | 기사 20건만. 테스트용 |
| `python -m rebrief collect` | 수집만 하고 원본 저장 |
| `python -m rebrief render --date 2026-09-06` | 저장된 원본으로 산출물만 재생성 |
| `python -m rebrief weekly` | 지난 7일치를 묶은 주간 결산 (`--end 2026-09-06`, `--no-llm`) |
| `python -m rebrief notify` | 오늘 결과를 텔레그램으로 (`--failed` 는 실패 알림) |
| `python -m rebrief titles show` / `titles log --date … --kind … --pick N --views X` | 제목 후보 보기 / 고른 것 기록 |
| `python -m rebrief publish --date … --url … [--views N]` | 발행한 글 주소 기록 (사이트에 '발행함' 표시) |
| `python -m rebrief site` | 휴대폰용 사이트 생성 (`site/`) |
| `python -m rebrief doctor` | 피드 상태 점검 |

공통 옵션: `-v` (상세 로그), `--config <폴더>` (설정 경로 지정)

기사를 다시 긁지 않으니 빠르고, 그날의 수집 결과는 그대로 유지됩니다.

## 문제 해결

**`python` 을 쳤는데 아무 반응이 없어요**

- **macOS**: `python` 이 아니라 `python3` 입니다. `python` 은 원래 없습니다.
  `python3 --version` 을 쳐 보세요. 이것도 안 되면 파이썬 설치가 필요합니다 → `bash setup.sh`
- **Windows**: 마이크로소프트 스토어가 열리면 아직 설치가 안 된 것입니다.
  [python.org](https://www.python.org/downloads/) 에서 받으면서 **"Add python.exe to PATH"** 를 꼭 체크하세요.
  또는 `setup.bat` 을 더블클릭하면 안내가 나옵니다.
- 애초에 설치가 번거로우면 **방법 A(GitHub Actions)** 를 쓰세요. 로컬 파이썬이 전혀 필요 없습니다.

**`ModuleNotFoundError: No module named 'feedparser'`**

가상환경을 켜지 않았거나 패키지 설치가 안 된 상태입니다.

```bash
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

**피드가 전부 실패해요**

개별 피드 문제가 아니라 네트워크·방화벽 문제일 가능성이 큽니다.
이럴 때는 `sources.yaml` 을 건드리지 마시고, 다른 네트워크에서 다시 시도하거나
**방법 A(GitHub Actions)** 로 돌려 보세요.

**수집은 되는데 요약이 안 나와요**

`ANTHROPIC_API_KEY` 가 없거나 잘못된 상태입니다. `prompt-pack.md` 가 대신 생성됐는지 확인하세요.
그 파일을 챗봇에 붙여넣으면 같은 결과를 얻을 수 있습니다.

## 구조

```
rebrief/
  collect.py     RSS 수집, 제목 정규화, 중복 제거, 본문 추출

  rank.py        이슈 점수 (보도량·키워드·최신성·매체·속보)
  llm.py         Claude 호출. 구조화 출력으로 Pydantic 모델 직접 수신
  prompts.py     프롬프트 3종 + 키 없을 때 쓰는 프롬프트 팩
  render.py      마크다운·네이버 HTML·SRT·JSON 생성
  images.py      수치를 인포그래픽 SVG 로. 크롬이 있으면 PNG 도
  weekly.py      일주일치를 묶은 주간 결산
  linkcheck.py   출처 링크 생존 확인
  checklist.py   발행 전 점검표 (금지 표현·분량·자리 검사)
  verify.py      브리핑 수치를 기사 원문과 대조
  notify.py      텔레그램 알림
  store.py       수집 이력·비용 장부·수치 시계열·제목/발행 기록 (state/)
  keynumbers.py  오늘의 핵심 수치 고르기 + 수치 토큰 규칙
  sanitize.py    모델 출력 HTML 에서 실행 가능한 조각 제거
  site.py        output/ 을 휴대폰용 정적 사이트로 변환
  pipeline.py    전체 조립
  cli.py         명령줄
  templates/     산출물 서식 (여기만 고쳐도 결과 형식이 바뀝니다)
config/
  sources.yaml   피드 목록 + 키워드 사전
  settings.yaml  파이프라인·영상·블로그 설정
```

같은 기사를 이틀 연속 다루지 않도록 `state/seen.json` 에 이력을 남깁니다
(기본 3일, `run.skip_recent_days` 로 조절).

## 알아 둘 것

- **수치는 반드시 원문과 대조하세요.** 프롬프트에서 "자료에 있는 내용만 쓰라"고 강하게 묶어 두었지만,
  숫자를 그대로 발행하기 전 확인하는 습관이 안전합니다. `production-notes.md` 4절에
  모델이 스스로 표시한 "확인 필요" 항목이 모여 있습니다.
- **RSS 는 제목과 요약만 주는 경우가 많습니다.** 본문 수집이 막힌 매체는 요약 근거가 얕아집니다.
  피드 점검으로 언론사 직접 피드를 최대한 살려 두는 게 품질에 가장 크게 기여합니다.
- **이슈 묶기는 완벽하지 않습니다.** 같은 지역·자산을 다룬 다른 기사가 한 이슈로 묶일 수 있습니다.
  자주 그러면 `cluster.similarity_threshold` 를 0.45 정도로 올리세요 (근거는 `cluster.py` 주석 참고).
- 투자 자문이 아닙니다. 생성물에는 면책 문구가 자동으로 붙습니다.
